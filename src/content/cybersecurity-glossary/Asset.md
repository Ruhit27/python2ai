Anything an organization values and might need to protect. That includes the obvious — customer data, laptops, servers, the website — and the less obvious: staff, a building, a domain name, or the account used to pay suppliers.

Security starts with knowing your assets. You can't protect a server nobody knows exists, and forgotten assets (an old test website, an unused cloud account) often become the easiest way in, adding to the [attack surface](./Attack%20surface.md). Many organizations keep an asset inventory for this reason.

Assets aren't all equally important. [Data classification](./Data%20classification.md) labels information by how sensitive it is, and a [risk assessment](./Risk%20assessment.md) weighs each asset's value against the [threats](./Threat.md) it faces, so effort goes where it matters most. Critical assets need a [backup](./Backup.md) plan so they can be restored after an incident.

_Avoid:_ "asset" as only hardware — data, accounts, and even people are assets too.

_Usage:_

"Why do we need a list of every laptop?"

"You can't protect assets you don't know you have — and you can't wipe a stolen laptop you never tracked."
